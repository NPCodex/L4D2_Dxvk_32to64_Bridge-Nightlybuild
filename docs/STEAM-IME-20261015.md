# Steam Overlay 中文输入与快捷键修复

v1.5.16 解决 Steam Overlay 中文输入不可用、Win+Space 只弹出开始菜单、切换中文后 Shift+Tab 不能关闭，以及确认中文候选词后整词重复的问题。维护者已在实际 Steam GameID 550、默认 x64 Host 的修复候选中确认微软拼音与微信输入法输入不重复，连续确认相同内容保留正确次数，快捷键正常；随后确认 Overlay 网页输入框也正常。

## 实现范围

Presenter 线程初始化并清理自身拥有的 COM/TSF 引用，首次前台 Steam 捕获时通过短生命周期 EDIT 预热原生输入上下文。上游 helper 来源为 L4D2 `4d61407e3df0e218d40a096c5359c90c18f53eba`，已包含在当前 partial `cafc044` 中。

完整 Windows 组合键和抬键交给系统；Steam 原生捕获时保留实际 OS 队列输入，保留子窗口及临时 IME 窗口焦点。已有 250 ms 定时器补充丢失焦点恢复，没有新增独立定时器或每帧任务。

Steam Renderer 11.12.30.07 的 x86/x64 WH_CALLWNDPROC 观察钩子先读取并提交 GCS_RESULTSTR。原窗口过程随后默认处理同一结果可能再产生字符。仅在 Steam 原生捕获期间阻止该结果消息的默认处理，保留其他输入路径；不按文本或时间去重，不吞掉用户再次确认的相同词语。诊断默认关闭，结果诊断有上限且不记录输入文本。

## 验证与边界

候选三端使用本地 MSVC 14.51 编译；286 个最终源码收据、架构和三端身份已核对。IME 生命周期 x86/x64 各 319 断言，键盘路由各 88 断言，提交边界各 280 断言通过；精确旧实现分别在 Win+Space 和重复默认处理断言失败。便携回归直接使用实际生产源码或提取函数，并保留适配器边界，不把模拟默认窗口过程视作真实 Steam 行为。

真实 Presenter 窗口覆盖两种混合进程架构；无定时器的 x64 负对照有效失败，反向 x86 负对照因前台获取超时未执行。早期隔离游戏 GameID 0 无法完成 Overlay 验收、第一候选中文重复，以及其他历史失败均保留；最终用户实测属于独立的默认 x64 游戏证据。正式 CI 使用 MSVC 14.29 并执行所需原生回归、最终源码与安装包校验。

没有 x86 Host 游戏验收、新 FPS、加载时间或长会话性能数据。上述 Steam Renderer 机制不保证所有未来版本；此修复不代表完整合并 L4D2 main，不采用新 NVIDIA pin、工坊更新器、其他跳过组或重新开展 ReShade 调查。wire schema 未改，源码身份改变，Client 与两个 Host 仍须配套。
