## Source finding and isolated change

Client `HookedGetAsyncKeyState`, `HookedGetKeyState`, `HookedGetKeyboardState` and `HookedGetCursorPos` return neutralized/virtual values while Bridge UI is active, without calling their stored original API chain. Earlier WH_* delegation does not change these query boundaries. Thus downstream API hooks can be skipped even though the immediate polling callers are game/MOD libraries. Existing logs do not prove that a skipped downstream hook belongs to Steam; this is a concrete chain boundary, not an established sole cause.

`client.steamPollChainPassThrough=True` requires client.steamOverlayInput, known actual Steam activation and current Bridge UI-active state. Each affected getter invokes its stored original exactly once, retaining original arguments for scalar keys; then the game still receives zero key states, an all-zero keyboard array or the existing virtual cursor echo. Keyboard/cursor originals write into small stack scratch buffers, not game output buffers or cursor caches. Suppressed-path LastError is restored. Original query failures retain the existing game's neutralized success/results; invalid UI keyboard output now fails explicitly rather than writing through null. Inactive/unknown Steam, disabled/master-off and ReShade-only UI retain the previous policy. Ordinary gameplay delegates normally with original results/errors.

GetAsyncKeyState may consume the Win32 legacy pressed-since-last-query bit; original APIs and downstream hooks can have side effects. This experiment intentionally allows that original behavior while preventing real returned key/cursor values reaching the game. It cannot guarantee arbitrary downstream MOD hooks have no independent side effects. No cursor setter is delegated while UI-active, no physical input is generated, and raw-input/DirectInput behavior is unchanged. Raw input already calls its original before neutralizing data. There is no new thread, Host detour, map, upload, Steam initialization/activation or foreground override. All defaults remain off, C1.

Diagnostics record `action=poll-chain-neutralize` at the affected original-call boundaries. This proves Bridge delegation, not Steam consumption. Bounded suppression-site deduplication now includes action so one call site's neutralize-to-delegate transition is not hidden. No new input contents are logged. The cold CreateDevice log now distinguishes `game_focus` and actual `backend_focus`: source already passes the Host child as both backend focus and presentation window; the earlier `focus` log printed the game argument and was misleading. No backend routing change is made.
