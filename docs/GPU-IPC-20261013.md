# v1.5.4 GPU 与 IPC 改动及验证范围

维护者在审阅两类候选结果后，于 2026-10-13 明确决定将它们一同合入新版本。本次选择 GPU 的原始 `DontUnroll` 候选，`None` 是同一位置的替代方案，没有同时采用。旧测试失败与收益不稳定的记录保持原结论；本次采用决定不是把失败改写为通过。

## 实际改动

IPC `MessageQueue::finish()` 省去空批次立即发布前的计时读取和临时 deadline 设置（flush 中原有的清零仍保留）；立即发布失败时仍恢复 pending deadline。批量 C8 的延迟发布、故障关闭及取消保护保留。仅一个 header 有运行时逻辑改动；累计补丁 SHA256 为 `431d083140c0275ee4bd80913c29ff482e9fcc3af1126355bd8b626390fd7810`。候选 LF header SHA256 为 `20cc61cbc1af4e29aa32d5974409100c21909c9067227be630463fac6c33be84`，此前 CRLF 测试副本为 `fe4408e0bd35cf72e963c530fe5444a4cbc37b27e98f923b0676027e806f6056`，内容仅换行格式不同。

GPU 改动位于独立固定的 GPLALL 2.6.8-2 后端，不是 NVIDIA RTX 渲染器。`dxvk_blit_frag_2d_ms.frag` 的 linear/nearest MSAA 循环从 `Unroll` 改成 `DontUnroll`；平均 resolve 循环保留原提示，采样数、alpha 加权、阈值、零权重回退及边界坐标未改。

固定 GPLALL 源提交为 `6a0ea561f9add008899680e6c313aa21c151e03e`。原源码重编与捕获 SPIR-V 逐字节一致；候选源码重编与只改 word 1178 的 SPIR-V 一致。原 shader SHA256 为 `e879efae72d147585afa2814ad7e5a4e04d0543d1a39f37b7e2bab212cb17a37`，候选为 `4a99ba7d328be8a1bed42dd761a08a6edabfda788cb523414a036a728c9dce18`。制作两个后端时验证原 ZIP、原 DLL、shader 唯一位置及最终 DLL SHA256，仅替换其中一个字节；这不是重新编译完整 GPLALL DLL。源码、变换规则和原许可留在仓库，玩家不需运行工具。

NVIDIA 构建源仍为 `d2a5033ec79303fffc33ca8e6595dd560162ff69`。L4D2 完整同步基准仍为 `c8d55b0f5d913d71488266469b4dca236439a4e9`，`677653d5d6751377799187c0677ff1e7d3f2f9ad` 仍是选择性采用；本次没有新的上游同步。

## 数值与原生正确性结果

真实开灯帧 EID1474 为 3840×2160 RGBA16F 8×MSAA 到 1024² 单采样的 FILTER_LINEAR 操作。原件替换与恢复对照均逐字节一致；`DontUnroll` 中间输出有 26 个 RGB 分量相差 1 half ULP，最大绝对差 0.000244140625，最终 4K 图像完全相同。因此原先的中间输出逐字节一致门槛失败，不能声明所有画面等价，也未据此证明可见画质退步。

x86/x64 显式 DLL 原生测试覆盖 1/2/4/8×MSAA、8 种 alpha/HDR 模式和 7 种缩放/resolve 操作，每个进程 224 用例全部执行，没有不支持或调用失败。每组对照有 4 用例、7 个 half 分量不同，均为 1 ULP，最大绝对差 0.00390625。第一次测试中十进制 alpha 转换的期望问题以精确可表示输入修正；另有基线和候选相同的正零/预期负零差异，原失败记录保留并单独说明。完整逐字节矩阵没有通过，这些测试工具期望问题不掩盖真正的候选差异。

IPC 新增可重复用例在本地 MSVC 14.51 上通过：双架构共 52 正例，2 个移除必要 fallback 的精准负对照按预期失败，Client32 四写者、2048 命令并发通过。提取器读取已准备源码，不会暗中应用候选，源文件前后哈希一致。正式构建中三端 Bridge 和新增 IPC 套件使用 MSVC 14.29；其他继承原生套件可能使用 runner 默认工具集，实际版本以每项收据为准，不能统称全部测试都用 14.29。发布要求完整 CI 通过，并逐文件比对 285 个 Bridge 源码与后端变换收据。

## 性能证据与限制

采用授权后，对同一已有帧执行两次预热/版本及六组平衡顺序配对；原版和候选都采用 shader 替换以平衡管线重建。

| 配对 | 顺序 | 原版 EID1474 (µs) | 候选 (µs) | 耗时变化 |
|---|---|---:|---:|---:|
| 1 | AB | 213.504 | 216.832 | +1.559% |
| 2 | BA | 223.648 | 214.688 | −4.006% |
| 3 | BA | 213.952 | 224.672 | +5.010% |
| 4 | AB | 213.376 | 214.976 | +0.750% |
| 5 | AB | 213.792 | 215.136 | +0.629% |
| 6 | BA | 213.664 | 213.952 | +0.135% |

目标配对中位耗时增加 0.689%，六组中五组变慢。EID948 这个小事件也六组变慢，中位约增加 1.088 µs / 20.56%；EID567 五组变慢，中位约增加 1.136 µs / 5.66%。这些其他事件观察没有单独建立与 shader 改动的因果关系；两侧另有孤立异常值，全部保留。没有 GPU 提速证据；不能把这组有限回放写成已证明游戏 FPS 下降或无回退。事件区间可能重叠，不能求和作为 GPU 帧预算，也不能从 Present 间隔中相减推算 CPU 成本。

IPC 之前的八轮、四组配对结果仍是历史证据：开灯平均提交率 / 1% low / 0.1% low 中位数变化为 +1.649% / −0.227% / +3.713%，关灯为 +1.964% / +1.865% / +2.451%。配对及 AB/BA 方向矛盾，未证明稳定收益。这些为本地 MSVC 14.51 构建的 Host Present 提交间隔指标，不等于最终显示 FPS，也不是当前正式 MSVC 14.29 组合版本的性能结果。

本次未进行组合版本游戏性能对照或新的游戏帧捕获，没有全场景画质、真实 Steam 交互或长期稳定性结论。诊断采样版不进入玩家包。原 E: 玩家安装保持只读。
